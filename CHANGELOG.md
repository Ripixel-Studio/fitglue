# Changelog

Hand-written since F1.8 of the single-user conversion; entries below
16.64.7 were generated by standard-version, which is gone.

## Unreleased

### feat!: re-point Pub/Sub, schedulers, webhooks and the parkrun agent at the box (rethink F3.4)

The inputs now arrive on the box through Funnel (`docs/guides/box-cutover.md`,
`deploy/box/cutover.sh`); Cloud Run keeps running until the cut-over's proof
step makes it unreachable, and F4 deletes it.

- `terraform/pubsub.tf`: every push subscription's endpoint is
  `https://jarvis.tail3065f7.ts.net/fg/pubsub/<svc>/<path>` with
  `oidc_token.audience = https://jarvis.tail3065f7.ts.net/fg/pubsub` (must equal
  `PUBSUB_PUSH_AUDIENCE` in `~/.jarvis/fitglue.env`; signing accounts unchanged).
- Removed `terraform/scheduler.tf` (weekly/monthly/yearly roundup,
  parkrun-results-check). Replaced by systemd user timers in `deploy/box/`
  (`fitglue-roundup-{weekly,monthly,yearly}.timer`, `fitglue-parkrun-check.timer`),
  same schedules and message bodies, wanted by `fitglue.target`, linked by
  `install.sh`.
- Added `fitgluectl trigger <roundup|parkrun-check|topic-…> [--data json]
  [--attr k=v] [--dry-run]` — what the timers run.
- Removed the `pubsub_self_invoke` run.invoker grants in `cloud_run.tf`; a push
  at a Cloud Run URL is now 403.
- Added `deploy/box/cutover.sh` (`--check`, `--start`, `--pubsub`, `--parkrun`,
  `--strava`, `--scale-down-cloud`, `--rollback`) and `docs/guides/box-cutover.md`
  with the Strava delete+create, the Fitbit console values and the Hevy
  `/v1/webhook-subscription` calls. Cloud Run rejects `max-instances=0`, so the
  "scaled to zero" proof is `--ingress=internal`, recorded and reversible.
- The box parkrun agent (jarvis repo, `scripts/parkrun_agent.py`) reads
  `~/.jarvis/parkrun-agent.env` to call `http://127.0.0.1:8104` with the
  `fitglue-box` key, minting its token for `https://127.0.0.1:8104`.
- `install.sh` links `fitglue-*.timer` and removes stale links such as
  `fitglue-api-public.service`.

### feat: list pending inputs on api-client (rethink J4)

- `GET /api/v2/users/me/pending-inputs` on api-client proxies the pipeline
  service's `ListPendingInputs` for the caller, so Jarvis can read James's
  pending inputs with the bearer token instead of Firestore.

### chore: secrets live in ~/.jarvis/fitglue.env on the box (rethink F3.5)

Every value the box units need is now in `~/.jarvis/fitglue.env` (mode 600):
the surviving Secret Manager secrets copied once under James's gcloud
identity, plus the per-box values (`PUBSUB_PUSH_AUDIENCE`,
`FITGLUE_PUBLIC_BASE_URL`, `WEB_URL`, `SITE_EXPORT_HOOK_URL`, `SENTRY_DSN`)
and the deployment settings the units also fix. Nothing on the box reads
Secret Manager; the `fitglue-box` SA has no `secretAccessor`.

- Added `deploy/box/env-check.sh`: diffs the file against
  `fitglue.env.example`, names only, exit 1 on a missing/empty required key.
- Added `docs/guides/box-secrets.md` (what lives where, rotation, loss).
- Caddy: `/fg/api/v2/oauth/*` → api-client, because `internal/oauthflow`
  builds the redirect_uri as `<FITGLUE_PUBLIC_BASE_URL>/api/v2/oauth/<p>/callback`
  and the base is `https://jarvis.tail3065f7.ts.net/fg`. `/fg/oauth/*` stays
  as an alias. Register the long form with the providers.
- `terraform/secrets.tf` is marked `RETIRED IN F4.2` with the exact list; the
  file and the `secret_key_ref` blocks stay until F4.1 removes the Cloud Run
  services, so an apply meanwhile does not roll a revision without secrets.
- Removed the `api-public` leftovers F1.5b missed in F3.1's files: the
  `BOX_SERVICES` entry (`make build-box` failed on `main`),
  `fitglue-api-public.service`, its `fitglue.target` line and port-table row.

### feat!: delete api-public (rethink F1.5b)

The unauthenticated `/api/public/*` gateway is gone: the public showcase is
now the static site at `james.ripixel.co.uk/life`, fed by `fitgluectl
export-site`, and `fitglue.tech/@james/*` + `/showcase/*` 301 there (S4.1).

- Removed `services/api-public`, `gateway/public.proto` and its stubs,
  `docs/api/gateway/public.openapi.yaml`, the service's Cloud Run / IAM /
  compose / CI entries.
- Removed the activity RPCs only api-public called: `GetPublicRoundup`,
  `GetRecentPublicRoundups`, and the `ListRecentRoundups` store method.
  `GetPublicShowcase`, `GetPublicShowcaseProfile`, `GetRoundup` and
  `ListAllRoundups` stay — the site exporter reads through them.
- `make generate` no longer produces `schema-public.ts` for the web app.

### feat: Caddy + Tailscale Funnel ingress for the box (rethink F3.3)

Public HTTPS for the box-hosted services, replacing Cloud Run's public ingress.

- `deploy/box/caddy/Caddyfile`: Caddy on `127.0.0.1:8100` (loopback only, no
  TLS — Tailscale Funnel terminates `https://jarvis.tail3065f7.ts.net:443` and
  forwards to it). Routes `/fg/webhook/*` → api-webhook `/api/webhooks/*`,
  `/fg/pubsub/{pipeline,activity}/*` → `/pubsub/*` on 8104/8105,
  `/fg/pubsub/destination/` → 8106 `/`, `/fg/oauth/*` → api-client
  `/api/v2/oauth/*`; everything else is an empty `404`. 10 MB body cap,
  timeouts, JSON access log at `~/.jarvis/logs/caddy-access.log` with
  `Authorization`/`Cookie` redacted.
- `deploy/box/fitglue-caddy.service`: systemd user unit, `Restart=always`,
  reload via a unix-socket admin endpoint. `deploy/box/caddy/install-caddy.sh`
  installs the pinned, checksum-verified static binary to `~/.local/bin`.
- `deploy/box/funnel.md` + `docs/guides/box-ingress.md`: Funnel on/off
  commands, the public URLs F3.4 re-points inputs at, security posture.
- Funnel is not yet allowed on the tailnet (needs the `funnel` node attribute
  — one admin-console click, see `deploy/box/funnel.md`); nothing is public
  until James enables it and runs `tailscale funnel --bg --yes 8100`.

### feat: build and run the services on the box (rethink F3.1)

The seven services can now run as systemd **user** units on the Jarvis box,
pointed at the same Firestore / GCS / Pub/Sub as Cloud Run. Nothing is cut
over yet; F3.4 does that.

- `make build-box` builds static `linux/amd64` binaries (CGO off) for every
  service plus `fitgluectl` and `bootstrap-owner` into `bin/`; `make deploy-box`
  builds, reloads and restarts the units that are active; `make status-box`.
- `deploy/box/`: one `fitglue-<svc>.service` per service on fixed loopback
  ports (api-webhook 8101, api-client 8102, user 8103, pipeline 8104, activity
  8105, destination 8106, api-public 8107), a `fitglue.target`, `install.sh`,
  and `fitglue.env.example` listing every key `~/.jarvis/fitglue.env` must hold.
- `infra.GRPCDial` accepts `http://host:port` targets (plaintext), which is
  what the units set in `*_SERVICE_URL`.
- Pub/Sub push endpoints (pipeline `/pubsub/*`, activity `/pubsub/roundup`,
  destination `/`) verify the subscription's OIDC token in-process when
  `PUBSUB_PUSH_AUDIENCE` is set (optionally pinned to
  `PUBSUB_PUSH_SERVICE_ACCOUNT`). On Cloud Run that check was done by IAM and
  nothing in the code looked at the token; on the box the endpoints are
  public via Funnel, so the check moves into the services. Unset keeps the
  old behaviour.
- `docs/guides/box-deploy.md` documents the layout, ports, env keys, logs and
  what is still cloud.

### feat!: single owner, static bearer token (rethink F2.1 + F2.2)

`api-client` no longer knows about Firebase Auth or about more than one user.

- Auth is `Authorization: Bearer $FITGLUE_API_TOKEN`, compared in constant
  time by `internal/server/middleware.go`. Missing, malformed or wrong token is
  `401`. Firebase ID tokens are rejected; the web app and mobile app can no
  longer call the API (they are being retired in the S-track).
- Every authenticated request acts as `FITGLUE_OWNER_UID`: handlers read the
  owner from the `Principal` the middleware sets instead of a JWT, so
  `GET /api/v2/users/me` returns the owner's existing `users/{uid}` document.
  The document shape is unchanged; integrations, counters, PRs, plugin
  defaults and booster data carry over untouched.
- `api-client` refuses to start unless both `FITGLUE_API_TOKEN` and
  `FITGLUE_OWNER_UID` are set.
- Terraform: Secret Manager secret `fitglue-api-token` (declared, adopted with
  an `import` block, value never in terraform — create the secret and its
  version with `gcloud` before the first apply) and variable `owner_uid`
  (`envs/prod.tfvars`) wired into the `api-client` Cloud Run service.
- `cmd/mcp` (`fitglue-mcp`) authenticates with `FITGLUE_API_TOKEN`.

#### Removed

- Firebase Admin initialisation in `api-client` and `api-webhook` (the latter
  held an auth client it never used). `infra.AuthVerifier`/`TokenInfo`
  (unused). The showcase-settings lazy display-name backfill that read the
  `name` claim off the JWT.
- `FITGLUE_ID_TOKEN`, `FITGLUE_REFRESH_TOKEN`, `FITGLUE_FIREBASE_API_KEY` and
  the Secure Token API refresh loop in `cmd/mcp`.
- `terraform/auth.tf` (Identity Platform sign-in config) and
  `identitytoolkit.googleapis.com` from the managed API list (left enabled in
  GCP; `disable_on_destroy = false`). `scripts/configure_auth_secrets.sh`.

#### Kept, deliberately

- `firebase.google.com/go/v4` in `go.mod` and `bootstrap.Service.Auth`: the
  showcase destination uploader still falls back to Firebase Auth for the
  owner's display name. Goes with that uploader's rewrite (S1.2).
- The Firebase web app and default hosting site in `terraform/firebase.tf`:
  `fitglue.tech` is still served from Firebase Hosting until S4/F4, and
  `outputs.firebase_web_config` feeds the web build.

### Added (rethink F2.3 — OAuth connect flow without the web app)

- `fitgluectl connect <strava|fitbit|github|spotify>` prints the provider's
  authorise URL — the same URL, state signature (`OAUTH_STATE_SECRET`) and
  callback (`<FITGLUE_PUBLIC_BASE_URL or API_URL>/api/v2/oauth/<provider>/callback`)
  the web app's `POST /users/me/integrations/{provider}/connect` produced.
  `fitgluectl connect hevy --api-key-stdin` stores the Hevy key and mints the
  webhook ingress key; `fitgluectl connect intervals --api-key-stdin
  --athlete-id` verifies and stores the Intervals.icu pair.
  `fitgluectl connections [--json]` lists connected providers with token expiry.
  `docs/guides/connect-sources.md` has the per-provider steps, including the
  Strava webhook subscription and Fitbit subscriber/`apiSubscriptions` calls
  F3.4 needs.
- `FITGLUE_PUBLIC_BASE_URL`: public origin for OAuth callbacks (and webhook
  URLs the CLI prints). Takes precedence over `API_URL`, which keeps working.

### Changed

- OAuth authorise-URL construction, state signing/verification and the
  callback URL moved from `api-client` into `internal/oauthflow`, shared by the
  CLI and the gateway. The callback's HTTP behaviour (redirect targets, error
  codes, token exchange) is unchanged. `api-client`'s `oauth_providers.go` is
  gone; `oauthflow.Provider` is the provider table.
- The `ingress_api_keys` write lives on `user.FirestoreStore.CreateIngressKey`;
  `api-client`'s `FirestoreApiKeyStore` delegates to it.
- `fitgluectl connect trainingpeaks` refuses with an explanation: no authorise
  configuration has ever existed for TrainingPeaks (only token refresh).
### Added (rethink S1.2 — export showcase changes to the site bucket on write)

- The activity service rewrites the site export after the writes that change
  it: `activity/<id>.json` after `AddShowcaseEntry` (both showcase uploader
  paths end there) and `RemoveShowcaseEntry`, `roundup/<key>.json` after a
  roundup is generated, then `index.json`, coalesced to one rewrite per 10 s
  burst. Background, best-effort: a failed export is a Warn line, never a
  failed upload or roundup. `SITE_EXPORT_SLUG` (default `james`),
  `SITE_EXPORT_BUCKET` (default the showcase-assets bucket),
  `SITE_EXPORT_DISABLED=1`, and `SITE_EXPORT_HOOK_URL` (POSTed after each index
  refresh; set on the box only). `fitgluectl export-site --all` remains the
  repair path. See `docs/guides/site-export.md`.

### Added (rethink F3.2 — fitglue-box service account)

- Terraform: `google_service_account.fitglue_box`
  (`fitglue-box@fitglue-server-prod.iam.gserviceaccount.com`, output
  `fitglue_box_sa_email`), the one identity the services use on the Jarvis box.
  Project roles `datastore.user`, `pubsub.publisher`, `pubsub.subscriber`,
  `aiplatform.user` (the AI banner still calls Vertex Imagen with ADC);
  `storage.objectAdmin` on the artifacts and showcase-assets buckets only;
  `run.invoker` on the `pipeline` Cloud Run service (what `parkrun-agent` has,
  so the box's parkrun agent can move to this key in F3.4(e)). No Secret
  Manager, no token creator. Created by hand first and adopted with an
  `import` block, as `fitglue-api-token` was. Key and verification steps in
  `docs/infrastructure/terraform.md`.

### Removed (rethink F1.8 — CI and Sentry)

- CircleCI `create-release` job: standard-version tagging and changelog
  generation, `version.json` in `gs://fitglue-server-prod-version-config`, and
  the cross-repo trigger of a `fitglue-web` rebuild. `npm run release` and the
  `standard-version` devDependency with it.
- CircleCI `build-and-test` on pull requests. GitHub Actions
  (`.github/workflows/ci.yml`: build, lint, unit tests) is the only PR check.
  CircleCI is now `main`-only and exists solely to run `terraform apply` and
  roll the Cloud Run images until F3/F4 move deploys to the box.
- `scripts/upload_sourcemaps.sh` (Sentry source maps for a Go-only server).
- Terraform variables `sentry_org` and `sentry_project` (unused). `sentry_dsn`
  defaults to empty instead of a non-DSN placeholder.
- The second Sentry initialisation in `bootstrap.NewService`; `infra.InitSentry()`
  in each service's `main` is the only one.

### Changed

- Sentry is a clean no-op without `SENTRY_DSN`: captures, `SentryHandler` and
  `Flush` return immediately, and the only trace is one Info line at boot. The
  environment tag comes from `ENVIRONMENT` (falls back to `local`), the server
  name from `SERVICE_NAME` or the Cloud Run service.
